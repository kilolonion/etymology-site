# 词条数据格式（backend/data/entries.json）

整本书的词条都放在 **一个 JSON 数组** 里，每个元素是一个词条对象。网站会监视这个文件，保存后约 2 秒自动重新加载，无需重启。

`backend/data/entries.json` 已收录全书词条（正文第 1–459 页，abet → zodiac，共 605 条，其中 6 条为跳转词条），与书末“词目索引”逐条对应。写法可参考开头的 abet → ambulance（第 1–13 页）。

**录入原则**：正文照原书转录；原书的排印错误一般照录（如 woman 的 Gascoinge、silicon 的 silium），只有与上下文自相矛盾的明显笔误才更正（如 magazine 原书“1939 年”改为 1739 年）。

## 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识，用作网址。小写、只含 `a-z0-9-`。由词头转换：去掉撇号，空格/斜杠变 `-`。例：`Achilles' heel` → `achilles-heel`，`Adam's apple` → `adams-apple` |
| `headword` | string | ✅ | 词头，保持书中大小写与写法 |
| `variants` | string[] | | 异体/另一种写法，如 `ageism/ agism` 中的 `agism`；搜索时也会匹配 |
| `ipa` | string | ✅ | 国际音标，**不带两侧斜杠**，照书转录（书用旧式记法，如 `ɔ`、`ɪ`） |
| `pos` | string | ✅* | 词性，照书原样：`n`、`v`、`adj`、`adv`、`adj & adv`、`n & v`… |
| `meaning` | string | ✅* | 【释义】原文，多个义项用全角分号 `；` 分隔 |
| `teaser` | string | ✅* | 🖊 一句话“钩子”：首页和推送通知里显示的问题，≤ 40 字，**不剧透答案** |
| `keyline` | string | ✅* | 🖊 读完后的“记住这一句”：一句话讲清来历，≤ 40 字 |
| `evolution` | string[] | ✅* | 🖊 词义演变时间线，2–4 步，从最早来源到今义，每步 ≤ 18 字 |
| `etymology` | string[] | ✅* | 【词源】正文，**按书中自然段拆成数组** |
| `examples` | object[] | ✅* | 【例句】，每条 `{ "en": "...", "zh": "..." }`。极少数词条原书没有【例句】（如 atlantic、derrick、q-tip），为保证阅读体验已补写 1–2 条，不能留空数组 |
| `seeAlso` | string[] | | 书中“参见 xxx”指向的词条 `id` |
| `links` | object[] | | 书外整理的词条关系，每条 `{ "id": "目标 id", "type": "同根" \| "同典故" \| "衍生", "why": "一句理由" }`。**一对只记一边**（约定记在 id 字母序靠前的词条上），网站加载时自动补成双向；已经是 `seeAlso` 的不用再记。见下方“词条关系” |
| `themes` | string[] | ✅* | 题材分类，1–3 个，**只能从下方固定列表中选** |
| `langs` | string[] | | 词源涉及的语言（从下方推荐列表中选，可为空） |
| `subtheme` | string | | 子专题。目前只有“风俗与生活”分了子专题（见下方列表），属于它的词条都要填一个 |
| `era` | number | | 故事起点所在的世纪：正文里提到的最早年代，`16` 即 16 世纪，公元前为负数（`-5` 即公元前 5 世纪）。“时间长廊”按它排列；正文没提年代就不填 |
| `page` | number | ✅ | 书中页码（正文页码，不是 PDF 页码；PDF 页码 = 书页码 + 7） |
| `redirect` | string | | 只用于“见 xxx”式的跳转词条（如 `also-runner 见 also-ran`），值为目标 `id`。有 `redirect` 时，带 * 的字段都可以省略 |

🖊 = 书里没有、需要根据词条内容另写的字段（编辑字段）。校验时缺少编辑字段只报警告，但正式数据应当补齐——它们决定了每日阅读的体验。

## 编辑字段怎么写

以 alcohol 为例：

```json
"teaser": "在变成“酒精”之前，alcohol 曾是埃及女王的心头好。",
"keyline": "阿拉伯语 al-kohl 原是女人涂眼皮的锑粉。",
"evolution": ["阿拉伯语 *al-kohl*：锑粉", "精细的粉末", "（借分馏法）酒精", "酒；含酒精的饮料"]
```

- **teaser** 是入口（首页和推送里只显示它，决定你想不想点进去）：制造好奇，抛出反差或悬念（“竟然”“为什么”），**不要直接说出来历**——比如 alcohol 不写“原本是涂眼皮的锑粉”，而写“在变成‘酒精’之前，alcohol 曾是埃及女王的心头好”。
- **keyline** 是文章结尾的“一句话记住”，具体、有画面感，最好带上关键原词。
- **evolution** 第一步写最早的来源（可带原词，用 `*斜体*`），最后一步写今义，中间写关键的转折。

## 文本约定

- **斜体**：书中斜体（例句里的目标词、词源里的外语原词、书名等）用 `*...*` 包起来，例如 `源自古法语 *abeter*（纵犬袭击）`、`the *Affluent Society*`。
- **中文引号**用 `“ ”`、`‘ ’`（全角），不要用 ASCII 的 `"`，以免 JSON 转义出错。
- 中文与数字/英文之间保留一个空格：`14 世纪`、`1835 年`。
- 例句编号 ①②③ 去掉，每句单独一个对象。
- 跨页、跨栏的段落要拼接完整，删除页眉（如 `abet · 1 · abet`）和侧边字母标签。

## 词条关系（links）

书里的“参见”很少（只有约 50 条词条有），所以另外整理了三种关系，用在文章页的“词的亲缘”和每日推荐里：

| type | 什么时候用 | why 的写法 |
|---|---|---|
| `同根` | 来自同一个外语词或词根 | 都源自拉丁语 *caput*（头） |
| `同典故` | 出自同一个神话人物、历史人物或同一件具体的事 | 都出自莎士比亚《奥赛罗》伊阿古挑拨一事 |
| `衍生` | 一个词的来历直接建立在另一个词上（派生、缩略、复合） | scape 是 escape 的缩略 |

宁缺毋滥：只是碰巧提到同一个人、同一位作家，或词头恰好有同一个英文单词，都不算。why 不超过 30 字，要具体、可核对。

## 子专题（subtheme）

“风俗与生活”词条太多（近 300 条），再分一层，每条只归一个：

```
饮食  衣饰容貌  居家器物  出行交通  岁时节令  婚恋家庭
身体情绪  众生百态  交际礼俗  消遣娱乐  花草风物  世情俗语
```

## 校验

```bash
npm run validate
```

会检查：JSON 能否解析、必填字段、编辑字段是否齐全与格式、`id` 格式与唯一性、`themes` 是否在列表内、`subtheme` 是否属于词条所在的专题、`links` 指向是否存在、类型是否合法、一对关系是否重复记录、`era` 是否在合理范围、`seeAlso`/`redirect` 指向的词条是否存在（不存在只给警告，因为可能还没录入）、`*` 是否成对。
